# 国内部署与数据迁移

截至 2026-11-07，原站仍由 Cloudflare Worker/R2 托管。本地新增 Node.js HTTP 后端沿用 `worker/api.ts`，支持本地文件系统和待云端验证的腾讯 COS 适配。此包是接手交付，没有完成国内上线。

## 本地启动

安装 Node.js 24，在「源码」目录依次执行：

```sh
npm ci
npm run typecheck
npm test
npm run build
npm run test:node
npm run start:node
```

打开 http://127.0.0.1:8788/ 。未配置 COS 时，数据默认写入「源码/.server-data」，关闭再启动需要保留此目录。构建仍会调用原 Vite/Cloudflare 工具链，输出 dist/client 和 dist/server；前者由 Node 提供静态文件，后者是 Worker 产物，不是 Node 入口。Node 直接运行 server/node-server.mjs，并依赖同目录源码、shared、worker、data 和已安装的依赖，不可只上传 dist/client。

`npm run dev` 和 `npm start` 仍保留原 Worker 开发用途。Node 运行时不使用 Sites 登录；不要重新增加账号或将 oai 身份头作为作者凭据。当前 Node 直接导入 TypeScript，推荐固定 Node 24，不使用旧版本 Node。

## 国内服务器接手步骤

1. 先在测试主机解压完整目录，安装锁定依赖并构建。此包不包含 node_modules 或构建输出，须在目标平台安装，不能复制 Windows node_modules 到 Linux。
2. 配置一个 Node 进程绑定 127.0.0.1:8788，Nginx 在同一主机提供 HTTPS 并代理所有请求，保留原 Host，覆盖设置 X-Forwarded-Proto。现有服务仅信任回环来源的该头；不同机器的反向代理不能直接套用本示例。
3. deploy/ 中提供 Nginx、systemd 和环境配置模板。按实际用户、路径、Node 路径、域名和证书修改后再校验，未在实际 Linux/Nginx/systemd 环境执行。域名上线按目标地区与服务商要求办理。
4. 首次测试可使用独立持久目录；线上使用时将 FORMSPACE_DATA_DIR 设置到代码目录外，限制文件权限并定期备份，更新代码不得清空数据。FS 存储包含 objects/ 与 meta/，停写或停服务后成对备份及恢复，不能只复制文件内容。
5. 要使用 COS，在测试桶配置真实凭据，验证下文全部项目后再切换。桶保持私有，媒体经 Node API 鉴权，不直接给浏览器长期云密钥或公开整个桶。
6. 用测试浏览器验证新建空间、上传、两版保存、发布/撤回、原件权限、删除、刷新和重启后读取、第二浏览器隔离，再进行桌面浏览器交互验收。通过后才搬正式数据、切流量，保留旧站与可回滚备份。

## 环境变量

| 变量 | 作用与默认值 |
| --- | --- |
| FORMSPACE_HOST | 默认 127.0.0.1，同机 Nginx 方案保持此值 |
| FORMSPACE_PORT | 默认 8788 |
| FORMSPACE_DATA_DIR | FS 对象和元数据目录，默认应用下 .server-data；生产应改为独立持久路径 |
| FORMSPACE_STATIC_DIR | 默认应用下 dist/client，可显式指定绝对路径 |
| FORMSPACE_DERIVED_GLB | 默认 data/models/arc01-mouse.glb，仅服务端读取 |
| FORMSPACE_COS_BUCKET | 非空时选择 COS，格式按实际桶名称 |
| FORMSPACE_COS_REGION | COS 实际地域，与桶一致 |
| FORMSPACE_COS_SECRET_ID / FORMSPACE_COS_SECRET_KEY | 仅服务器环境配置，按最小必要权限使用 |

node-server 不会自动读取任意 .env。systemd 用 EnvironmentFile 注入；手动运行可用 Node 24 的 `node --env-file=/私有绝对路径/server.env server/node-server.mjs`。不要使用 VITE_ 前缀传递云密钥。配置 COS 时四项都要齐全；变量缺失应排查错误，不以空数据启动来掩盖迁移失败。

## 存储适配的已知边界

FS 与 COS 条件写入目前依赖进程内串行锁，按单机单进程使用。不要启用 PM2 cluster、多个容器、多副本或多个服务共同写同一数据；扩容前必须改为跨进程可验证的并发控制并补测。

COS 代码已随源码提供，但没有真实凭据/真实云端验收，不能声明生产可用。WorkBuddy 应检查 SDK 返回的 Body 类型及流转换、ETag 与条件写、元数据保留、分页游标、批量删除逐项错误、Range/206/416、异常回滚、大文件内存及断线处理，并用真实测试桶验证后修复问题。测试文件本身也不等于已完成生产验证。

Nginx 上传上限需容纳 40 MiB 文件加 multipart 开销，模板给 45m 和 300 秒超时；应用仍保持 40 MiB 新增文件上限，不因代理放大而放开。影视大文件分片直传和通用 MAX 转换没有实现。

## 旧站作品、作者与收藏迁移

本包未导出任何远端会话、作者或私密历史。迁移数据时，以当前 API 的 sessions/profiles/records/versions/files 及兼容布局为准，保留索引/原 ID/公开展示和过程节点/下载设置；记录每对象元数据与 SHA-256，先备份再导入，校验数量、字节、权限和失败回滚。

旧域 Cookie 是 Host Cookie，改域名不会自动交给新域。即便复制 sessions/，原浏览器也不会自动在新域携带秘密。需要另行实现作者可验证、短期、一次性的安全迁移交接；不得把私密作品分给新站首位访客，不得通过 URL 或公开聊天导出 Cookie。现阶段没有该迁移入口，不要宣称已恢复旧作者权限。

收藏是旧 origin 的 localStorage 偏好，服务器搬家不会带走收藏。需要另外设计偏好导入，并且收藏 ID 不能扩大作品权限。内置五件与附带资源见 04_作品资源范围.md；它们不代表所有远端用户数据。
