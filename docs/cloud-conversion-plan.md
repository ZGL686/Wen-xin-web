# 长序：独立云端三维转换部署方案

## 决策状态

用户已确认需要独立云端自动转换：文件上传完成后，即使个人电脑关机、网页关闭，云端仍能继续处理。用户目前没有为转换服务准备云资源或凭据。

本方案为 **proposed**。建议先验证 Autodesk Platform Services（APS）的 3ds Max Automation，确认实际引擎、账号资格和真实 MAX2026 文件兼容性后，再决定正式接入。当前没有创建 APS 应用、购买云机、配置计费、提交真实云转换任务或部署转换服务。不能把本方案当作已上线能力。

## 当前项目边界

- 前端仍为 React + Vite + TypeScript，Three.js 提供网页模型浏览；网页预览当前支持 GLB、单文件 OBJ 和 STL。
- 后端仍为 Cloudflare Worker，作品、版本、附件与浏览器空间凭据保存在 R2。Worker 负责 HTTP、鉴权和存储，不承担原生 3ds Max 程序的运行。
- 本轮源码已允许原始工程不限后缀归档，原文件保留原名并作为附件下载；这不表示已经具备解析、转换、缩略图生成或网页运行能力。线上状态以发布及验收回执为准。
- 每次新增文件合计仍限制为 **40 MiB**，图片单张最多 12 MiB。此方案不暗中放大上传限制；大工程及贴图包的传输策略需要另行实现、验证。
- 已有四件作品的 GLB 与封面来自离线真实场景转换；专业工程不会因为保存成功就自动进入云队列。现有上传进度仅表示浏览器上传，不是转换进度。
- 新作品和新版本默认私密，作者选择的公开展示版与公开历史节点保持独立。云转换不能替作者做公开选择。

## 推荐路径：先验证 APS 托管引擎

APS 提供以 3ds Max Batch 执行 MAXScript、Python 和插件的托管能力，与本项目已经采用的原生读取、导出、验证流程方向相符。优先验证该路线，可以先避免维护一台长期运行的 Windows 转换主机；这是技术选型建议，不是对当前账户可用性或费用的承诺。[官方 Automation 概览](https://aps.autodesk.com/developer/overview/automation-api)

### 第一步：账号、凭据和引擎实查

1. 由项目所有者准备 APS 账号及应用，确认 Automation 服务是否对该账号开放、适用的计费与使用资格、支持的区域和配额。免费额度或试用资格必须以账号实际显示及当前官方条件核实，不将其作为项目永久免费运行的前提。
2. 获取服务端应用 Client ID、Client Secret，按官方要求使用 app-only OAuth 和所需权限。这些凭据仅进入服务端密钥配置，不写入仓库、前端、浏览器存储或公开交接文件。
3. 调用官方 `GET engines`，读取全部分页，查询候选引擎详情，保存实际返回的引擎 ID 和版本记录。**目前未核实存在可供本账号使用的 MAX2026 引擎**，不得凭名称猜测或把桌面软件版本当作云端引擎支持证明。[官方 API 参考](https://aps.autodesk.com/en/docs/design-automation/v3/reference)、[官方引擎枚举示例](https://blog.autodesk.io/design-automation-api-obtaining-supported-engines/)
4. 准备一个最小、可追溯的转换脚本及所需 AppBundle/Activity，先测试用户真实的 MAX2026 样本，再测试项目四件基线原件。使用副本执行，处理前后核对原件 SHA-256，不改写原件。
5. 只有实际成功读取、输出可验证的 GLB 和缩略图后，才把对应的输入版本、插件组合与场景类型列入“已验证支持”。引擎版本不匹配、必需插件缺失或无法生成有效结果时，不进入正式上线阶段。

### APS 的明确限制

官方文档列出：仅支持 `3dsmaxbatch.exe`，不支持依赖 UI 的操作和 ActionMan；没有 GPU；不支持加载或保存压缩 MAX；磁盘写入限任务工作目录。转换脚本与缩略图生成必须以这些限制为前提验证，不能承诺 GPU 渲染器或本机所有脚本可直接照搬。[官方限制](https://aps.autodesk.com/en/docs/design-automation/v3/developers_guide/restrictions)

3ds Max 2026 的原生 glTF 导出器支持 GLB，但官方说明 glTF Material 的效果更合适，其他材质不能保证等效；该导出路径不输出动画、蒙皮和 morpher 数据。因此，第一阶段目标是可交互查看的静态几何与尽力保留的基础材质，不承诺完整还原所有效果、动画或第三方着色器。[官方 glTF 导出说明](https://help.autodesk.com/cloudhelp/2026/ENU/3DSMax-Interoperability/files/GUID-5B4C8EC2-2230-4F9F-B3C6-48D9E347E37D.htm)

原场景引用的贴图、外部参照、字体或插件也需要准备与检查。缺失资源必须作为真实警告或失败原因返回；不能使用替代模型、虚构材质或生成图片冒充源工程的转换结果。输入包与压缩 MAX 是不同概念：把文件放进 ZIP 不会消除 MAX 自身压缩模式的限制。

## 需要准备的服务与配置

| 项目 | 用途与边界 |
| --- | --- |
| APS 应用、实际可用的 3ds Max 引擎、转换活动 | 执行真实原生场景读取和导出；活动版本固定并可追溯 |
| APS 服务端凭据与账号资格 | 申请任务和查询结果；不由访客提交凭据，不在网页暴露 Secret |
| 服务端任务记录与可靠投递机制 | 在上传提交完成后持久记录任务、重试、超时及外部任务 ID；浏览器关闭后继续运行 |
| R2 私密输入与输出存储 | 原件保持原字节；转换结果与日志按任务及源版本分开保存，不建立公开桶 |
| 临时签名输入/输出通道 | 允许外部转换器读取本次输入、写入本次指定结果；不依赖作者浏览器 Cookie |
| 回调验证或服务端轮询 | 核验供应商任务状态和返回对象；回调重复到达时仍只提交一次结果 |
| 运行配额、超时与清理配置 | 限制并发和资源消耗，清理临时文件；配额、耗时目标与费用在样本实测后确定 |

任务记录可以继续使用受控的服务端存储，可靠投递机制的具体产品待资源确认后选定。现有 Worker/R2 绑定不等于已经拥有 APS 应用凭据、通用 R2 S3 密钥或任务队列，不能假设这些配置已经存在。

## 私密传输与同版本回写

建议流程为：

1. 作者完成某一版本的原件上传和保存，服务端检查作者权限后，以 `workId + versionId + sourceHash + adapterVersion` 记录转换任务。只有任务实际提交成功才显示进入队列。
2. 服务端为指定输入和输出签发短效、限对象、限方法的访问能力。可使用受限的签名网关或已配置的私密对象存储签名 URL；具体方式须验证 APS 能否按预期下载与回传。不要把原件改成公开地址，也不要把浏览器 HttpOnly Cookie 传给 APS。Autodesk 官方示例采用临时输入下载和输出上传地址。[官方 3ds Max 示例](https://github.com/Developer-Autodesk/design.automation.3dsmax-postman-tutorial)
3. 转换器输出真实 GLB、PNG 或其他明确约定的缩略图，以及结构化验证报告。服务端核对任务身份、输入哈希、输出大小、文件格式和实际可读性；供应商返回成功不单独等于作品已转换成功。
4. 衍生结果只关联触发任务的 **同一作品、同一版本、同一输入哈希**。建议单独保存衍生资源记录，避免异步结果改写已保存的不可变内容快照。旧任务晚到不能覆盖新版本或用户另附的网页模型。
5. 结果写回不改变 `displayVersionId`、公开历史节点或原件下载开关。新私密稿的模型和缩略图不能替换旧公开版；文件读取仍按所属版本的作者权限和公开选择鉴权。
6. 作品已删除、任务已取消、输入哈希不符或版本已不可关联时，拒绝发布结果并清理临时产物。重复、伪造或乱序回调不能多建版本、认领其他空间或扩大公开范围。

任务内部密钥、签名地址、供应商令牌和原始日志不能进入公开作品 JSON。日志对作者显示前需脱敏。转换失败保留原件与已经存在的预览，明确提供失败原因、重试或手动补充预览的入口。

## 失败替代：独立 Windows 转换主机

若 APS 无适合的实际引擎，或用户 MAX2026、压缩场景、必需插件及输出需求无法通过验证，再评估独立 Windows 云机：安装固定版本的 Max2026，配合已验证的批处理脚本，必要时经受支持的中间格式交给 Blender 生成 GLB 和 CPU 缩略图。Max 负责原生 MAX 读取，不能把只安装 Blender 当作完整 MAX 转换方案。

该路线需要云账号与主机、受支持的 Windows、Max2026 及必要插件的可用服务授权、任务执行服务、隔离工作目录、存储访问、日志和监控。是否需要 GPU 和具体机器配置由渲染目标及真实样本测试决定。[官方 3ds Max Batch 说明](https://help.autodesk.com/cloudhelp/2026/ENU/3DSMax-Batch/files/GUID-0968FF0A-5ADD-454D-B8F6-1983E76A4AF9.htm)

上传工程在受限进程与独立工作目录中处理，不把未知工程或附带脚本当作可信代码执行。无论选择托管引擎还是云机，都需要为异常场景设定超时、重试边界和临时数据清理策略。

## 按适配器逐步扩大格式

“原件不限后缀归档”继续作为保存能力；自动预览按适配器单独支持。首批先做真实 MAX2026 静态场景验证，之后按实际需求接入其他原生工具或导入器，并记录输入版本、依赖、输出能力与已测样本。

对于未知、损坏、加密、缺少必需依赖或不兼容的工程，仍允许在现有约束内归档原件，并诚实显示“尚无网页预览”或转换失败。不能将任一适配器描述成“任何三维格式都能百分之百自动预览”。

## 实施阶段与验收标准

| 阶段 | 完成条件 |
| --- | --- |
| 资格与引擎验证 | 已确认账号资格、凭据配置方式、完整引擎列表及真实 MAX2026 读取结果；没有把未确认引擎写成已支持 |
| 单任务验证 | 真实原件生成有效 GLB 和缩略图；原件哈希不变；报告记录引擎/脚本版本、缺失资源及材质限制 |
| 私密联调 | 两个独立浏览器空间隔离；跨作者输入、输出、任务状态均拒绝越权；令牌及签名地址不进入公开响应 |
| 生命周期验证 | 上传提交完成后关闭浏览器、关闭个人电脑，任务仍由云端完成；重新打开原空间可以查看真实结果 |
| 版本与公开验证 | 新稿转换不改变旧公开展示；晚到结果不覆盖新版；重复回调幂等；删除、撤回及原件下载权限继续生效 |
| 故障验证 | 超时、无资源、格式不支持、缺贴图、输出损坏和回调丢失均有真实状态；原件与旧预览不被误删 |
| 正式接入 | 提供资源清单、运行和凭据配置说明、已测格式矩阵及真实网页验收回执；再明确宣布该范围已上线 |

界面只展示服务端可证实的状态，例如“尚未配置转换”“已提交”“处理中”“成功”“失败”。无上游精确进度时使用状态和真实时间，不模拟百分比、不从上传百分比推断转换完成，也不在资源尚未接入时生成假的排队任务。
