# 资产与公开仓库边界

## 目录职责

| 路径 | 保存内容及维护边界 |
| --- | --- |
| `assets/3d source/` | 原始三维工程；MAX 原件保持内容不变 |
| `assets/pipeline/` | 几何导出、转换脚本、中间模型、渲染图和资产验证资料 |
| `formspace/data/works.json` | 网站初始作品元数据 |
| `formspace/public/originals/` | 网站提供下载的原件副本 |
| `formspace/public/portfolio/` | 网站实际加载的 GLB、WebP 和验证清单 |
| `deliverables/` | 保留交付 ZIP 和对应校验文件；展开目录仅本地使用 |
| `wiki_memory/` | 单层工程记忆；记录结论、来源和关联 |

原件是事实来源，不能为适应网页展示而直接覆盖。派生模型、材质近似和预览图写入转换或网页目录。改变来源、尺寸或几何时应重新验证并同步元数据，不能只替换缩略图后沿用旧验证记录。

## 真实资产说明

初始四个 MAX 已保留哈希证据。网页 GLB 来自真实源几何，网页材质为基础色与粗糙度近似，不能标为完整还原 MAX 材质或离线渲染效果。模型查看器的归一化单位与物理尺寸分开记录；物理尺寸以验证清单为准。

2026-10-26 尊重用户将原件目录由 `assets/source/` 改为 `assets/3d source/` 的现有整理。验证工具和当前导入工具使用新路径，历史日志及旧交付包保留原时点的路径记录。四件网页基线的原件、下载副本与派生模型继续按验证清单核对。

该目录还保存新增原件 `ARC01_Mouse_3dsMax2026.max`（9,101,312 字节；实测 SHA-256：`e9918e40d1abb39338f38e70774681983e97ecdfe4320e7e9d6d24c021602bbb`）。它作为 Git LFS 管理的项目资料保留，目前不在网页四作基线或 `public/portfolio/verification.json` 中；尚未制作或验证其网页模型、封面及作品条目。不能将文件存在等同于已加入网页。

资源副本必须与 `data/works.json` 地址一致。更新公开原件前核对 SHA-256，保留 `public/portfolio/verification.json` 的来源说明，不用示意图或 AI 图片冒充实际模型验收。

## Git 与 LFS

主仓库按 [[决策/ADR-001-仓库与资产组织]] 组织。MAX、BLEND、FBX、GLB、ZIP 使用 Git LFS，具体匹配规则以根目录 `.gitattributes` 为准。仅有 LFS 指针不代表资产已经完整到本机；交付前检查 LFS 对象和实际文件。

公开仓库不收录真实令牌、私钥、登录凭据、环境变量值、运行缓存、调试日志、依赖目录或展开交付副本。`.env.example` 等样例只能保留变量名及无机密占位。忽略规则和文件名门禁不能代替内容审阅。

独立 Sites 应用的发布身份只在 `formspace/.openai/hosting.json` 维护。交接给新部署方的副本需要去除现站身份与凭据，防止新项目误更新原站；不能删除现行应用自身的 manifest 来绕过正常发布流程。

## 版本与记忆

实质工作结束后按 [[决策/ADR-002-每轮记忆与版本同步]] 同步短日志与版本。记录本轮变更、已执行验证、结果和遗留问题；旧日志与旧交付物保留历史，不通过覆盖历史伪装为新验收。
